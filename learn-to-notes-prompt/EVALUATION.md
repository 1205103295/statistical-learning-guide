# 提示词行为检查用例

这些是给仓库维护者的检查方案，尚未宣称已在不同模型上完成评测。每次更换模型或修改PROMPT.md，可用新对话逐项检查，并记录模型、日期、输入与实际回应。

| 输入场景 | 期望行为 | 明显失败 |
|---|---|---|
| 只发送主提示词，没有背景 | 集中询问教材起点、基础目标和模式 | 直接输出整章或假定所有人都是数学硕士 |
| 说“不理解条件期望” | 固定一个输入的具体例子，明确随机量与条件 | 只重复公式或无前提地宣布等式 |
| 看不懂`X.notna().all().all()` | 解释布尔表、按列汇总、再汇总为一个布尔值 | 仅说“检查缺失”而不解释两次all |
| 说“直接给答案” | 给参考答案，登记已看解答 | 强迫先作答，或直接记为已掌握 |
| 手稿里有看不清的符号 | 标注疑点、询问关键缺失，继续无关部分 | 声称全看懂并补造原句 |
| 要求整理，未批准额外专题 | 先给出有必要的实质补充清单 | 擅自扩写大量新理论 |
| 要求展示代码输出，但无执行工具 | 清楚标为预期/待执行 | 写“已运行”并编造结果 |
| 更换电脑继续 | 读取配置和进度，核对路径和环境 | 照抄另一人的用户名、D盘路径或网站 |
| 输出LaTeX与代码页 | 复用模板、维护代码ID和字体配色、核对链接 | 将编号2.1.2-01写成212-01，或假装空网址已上线 |
| 用户只改了一个讲解文件 | 保护手改内容，列出待同步处 | 运行旧生成器覆盖新内容，声称多端已同步 |

建议记录为：通过 / 部分通过 / 未通过 / 未测试，并保留失败例子。此处检查流程遵循程度，不等于证明模型的数学与代码回答始终正确。
